# 项目成果证据

## 问题—措施—证据

1. 旧项目在 JDK 21 下因编译器与 Lombok 不兼容而无法构建。
   - 措施：升级至 Spring Boot 2.7.18、Lombok 1.18.32，统一 Maven release 21。
   - 证据：`mvn test package` 可在 JDK 21 完成测试与打包。

2. 接口把业务失败包装成 HTTP 200，前端和日志难以区分参数错误、越权、资源不存在与状态冲突。
   - 措施：清理各 Controller 的异常吞噬，建立统一错误码和全局异常处理，使用 400/401/403/404/409/500 表达错误语义，并隐藏内部异常细节。
   - 证据：全局异常测试验证 HTTP 状态、稳定 `errorCode` 与安全错误消息。

3. 订单状态依赖散落的数字判断，容易跳过确认直接入住，或对已取消订单重复操作。
   - 措施：建立显式订单状态机，集中约束预订、确认、取消、入住和退房迁移。
   - 证据：自动遍历 5×5 共 25 种状态组合，只允许 5 条合法迁移。

4. 原鉴权由自定义 MVC 拦截器和注解分散实现，权限规则难以审计。
   - 措施：迁移至 Spring Security 无状态 JWT，集中配置用户/管理员 RBAC，保持前端 Bearer Token 协议兼容，并对部署时仍使用默认密钥给出启动告警。
   - 证据：安全测试覆盖匿名 401、普通用户越权 403、管理员放行及伪造令牌拒绝。

5. 项目缺少可复现性能证据，无法诚实量化接口表现。
   - 措施：增加 JDK 21 零依赖只读压测工具，统一输出成功率、吞吐量与 P50/P95/P99。
   - 证据：开发机以并发 20 完成 500 次客房列表请求，成功率 100%、P95 251 ms；脚本与环境说明可重复验证。

## 简历表述建议

- 对既有智慧酒店管理系统进行工程化治理，完成 JDK 21 构建迁移、统一接口错误语义和 Spring Security 无状态 JWT/RBAC 改造，解决旧项目无法构建、业务失败返回 200 及权限规则分散问题。
- 将预订—确认—入住—退房建模为显式状态机，以自动化测试覆盖全部 25 种状态组合，阻止越权操作和非法状态跳转。
- 建立 Maven/H2 自动化回归与 JDK 21 零依赖性能基准，输出成功率、吞吐量及 P50/P95/P99，为项目质量与简历数据提供可复现证据。

当前 JDK 21 全量构建包含 27 项自动化测试，全部通过。
